# ADR-002: Provenance Taxonomy and Multi-Class State Separation

## Context and Problem Statement
Smart city platforms and digital twins often suffer from "truth pollution", where simulated scenario outputs or ML predictions overwrite or get conflated with observed ground-truth telemetry. This undermines governance trust, makes auditing impossible, and leads to invalid research claims.

## Decision Drivers
- Governance integrity and auditability.
- Clear user comprehension across all UI displays.
- Strict compliance with academic research standards (simulation ≠ field data).

## Decision Outcome
We establish a non-negotiable **6-state provenance taxonomy**:
1. `LIVE`: Directly observed from authenticated field sensors/APIs.
2. `REPLAY`: Historical time-stamped series ingested via replay publishers.
3. `SIMULATION`: Behavioral outputs generated by SUMO or synthetic generators.
4. `PREDICTED`: Inference values generated by trained forecasting models.
5. `STALE`: Records whose age exceeds the domain freshness threshold (e.g., > 180s for corridor traffic).
6. `INVALID`: Records that fail sanity or schema validation.

### Database Separation
- `telemetry_observations`: Hypertable partitioned by time, storing raw observations with explicit source mode.
- `twin_current_state`: Latest authoritative snapshot derived ONLY from valid `LIVE` or `REPLAY` records.
- `forecast_records`: Dedicated table storing model forecasts tagged with `PREDICTED`.
- `scenario_runs` & `scenario_kpis`: Isolated tables for simulation runs tagged with `SIMULATION`.

## Invariants
1. Forecasts and scenario simulations **never** mutate `twin_current_state`.
2. Every UI card, chart, and map element must render a visual provenance badge.
